# 组网测试记录

记录日期：2026-10-10。以下实测结论来自使用者在 Windows、Android 和 macOS 上的反馈，不代表所有平台或长期稳定性均已验证。

## Windows 实测

| 项目 | 结果 |
| --- | --- |
| 管理员身份启动并获取虚拟 IP | 通过 |
| 与官方客户端节点通信 | 通过 |
| 权限不足时明确提示 | 通过 |
| 与另一个软件使用相同虚拟 IP 时冲突提示 | 通过 |
| 同一进程多个网络同时连接，各子网可以 ping 通 | 通过 |
| 单独停止或重启一个网络，其他网络继续通信 | 通过 |
| 停止全部网络，无意外停止误报 | 通过 |

“停止全部”曾误报核心意外停止。插件已修复停止时序，自动化回归测试和 Windows 真机复测均通过。

## Android 实测

| 项目 | 结果 |
| --- | --- |
| 启动组网并连接 | 通过 |
| 返回桌面后 VPN 保持运行 | 通过 |
| 后台运行数分钟后重新进入，恢复连接状态且不重复启动 | 通过 |
| VPN 路由掩码计算修复后的启动 | 通过 |
| 停止和重启 | 通过 |
| 最近修改后的后台返回与连接恢复 | 通过 |
| 拒绝 VPN 授权后再次启动 | 通过 |
| 无效配置错误提示 | 通过 |
| Wi-Fi 与移动网络切换后恢复通信 | 通过 |
| 错误服务器地址触发启动超时提示 | 已确认；停止、修改并重试仍待确认 |

启动闪退的崩溃日志显示 `VpnService.Builder.addRoute` 抛出 `Bad address`。插件已按实际前缀长度计算网络地址，替换原先只适用 `/24` 的计算方式，并将 VPN 创建异常返回给 Dart。

## macOS 实测

| 项目 | 结果 |
| --- | --- |
| GitHub Actions 构建 macOS 测试包 | 通过 |
| GitHub macOS 环境无 TUN 入网，本地发现节点并建立 P2P | 通过 |
| 本地 ping 云端节点虚拟 IP | 通过；由核心无 TUN 模式回复 |
| 真实 Mac 管理员启动应用并使用 TUN 组网 | 通过 |
| Mac 通过组网访问目标 TCP 服务 | 通过；使用 ADB 连接和读取手机型号验证 |

ADB 仅作为 TCP 通信验证工具，本记录不包含投屏或其他应用功能的验收。
macOS 多组网隔离、异常恢复和长期运行仍需验证。

## 自动化检查

最近代码检查：插件 35 项测试、Demo 8 项测试通过，Flutter 静态检查无问题。其中包含“停止全部返回前先收到停止事件”的回归场景。自动化测试不代替真机网络验证。

## 待验证

- 错误服务器地址超时后，修改地址并重新启动。
- 长时间后台运行、系统回收进程。
- 代理网段访问，以及 `manualRoutes: []` 禁用代理路由后的行为。
- 断网一两分钟后恢复通信。
- Android 锁屏后台半小时以上后的状态和通信。
- 强制结束应用进程后重新打开并启动。
- 连续启动、停止十次，检查端口、网卡和页面状态。
- macOS 多组网隔离、异常恢复和长期运行。
- iOS、Linux 的运行与权限流程。
- OpenHarmony 原生接入和真机运行。

当前 Android 仅支持一个系统 VPN 会话；Windows 的多组网通过结论不推广到其他平台。
