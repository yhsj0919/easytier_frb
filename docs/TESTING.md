# 组网测试记录

记录日期：2026-10-09。以下实测结论来自使用者在 Windows 和 Android 上的反馈，不代表所有平台或长期稳定性均已验证。

## Windows 实测

| 项目 | 结果 |
| --- | --- |
| 管理员身份启动并获取虚拟 IP | 通过 |
| 与官方客户端节点通信 | 通过 |
| 权限不足时明确提示 | 通过 |
| 与另一个软件使用相同虚拟 IP 时冲突提示 | 通过 |
| 同一进程多个网络同时连接，各子网可以 ping 通 | 通过 |
| 单独停止或重启一个网络，其他网络继续通信 | 通过 |
| 停止全部网络，无意外停止误报 | 通过 |

“停止全部”曾误报核心意外停止。插件已修复停止时序，自动化回归测试和 Windows 真机复测均通过。

## Android 实测

| 项目 | 结果 |
| --- | --- |
| 启动组网并连接 | 通过 |
| 返回桌面后 VPN 保持运行 | 通过 |
| 后台运行数分钟后重新进入，恢复连接状态且不重复启动 | 通过 |
| VPN 路由掩码计算修复后的启动 | 通过 |
| 停止和重启 | 通过 |
| 最近修改后的后台返回与连接恢复 | 通过 |

启动闪退的崩溃日志显示 `VpnService.Builder.addRoute` 抛出 `Bad address`。插件已按实际前缀长度计算网络地址，替换原先只适用 `/24` 的计算方式，并将 VPN 创建异常返回给 Dart。

## 自动化检查

最近代码检查：插件 35 项测试、Demo 8 项测试通过，Flutter 静态检查无问题。其中包含“停止全部返回前先收到停止事件”的回归场景。自动化测试不代替真机网络验证。

## 待验证

- Android VPN 拒绝授权、无效配置等错误提示场景。
- 长时间后台运行、系统回收进程及网络切换。
- iOS、macOS、Linux 的运行与权限流程。
- OpenHarmony 原生接入和真机运行。

当前 Android 仅支持一个系统 VPN 会话；Windows 的多组网通过结论不推广到其他平台。
